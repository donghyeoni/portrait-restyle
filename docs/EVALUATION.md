# 평가 지표

Phase 1 스윕이 뱉는 수백 장을 사람이 눈으로 비교하는 것은 불가능하다.
세 축을 숫자로 뽑아 자동 랭킹한다.

## 왜 Phase 1보다 먼저인가

스윕 1라운드만 80~240장이 나온다. 판정 기준 없이 눈으로 고르면
(a) 재현이 안 되고 (b) 화풍이 늘어날 때마다 처음부터 다시 봐야 하며
(c) 저해상도 입력(test2/3/4)의 불리함과 워크플로우의 문제를 구분할 수 없다.

평가 스크립트는 GPU를 거의 쓰지 않는 순수 개발 작업이므로,
Phase 1 스윕을 돌리기 전에 만들어두는 것이 총 일정을 줄인다.

## 세 축

### 1. 정체성 유지 — ArcFace 코사인 유사도

원본 증명사진과 결과물에서 각각 얼굴 임베딩(512차원)을 뽑아 코사인 유사도를 계산한다.

- 검출: `scrfd_10g_bnkps.onnx`
- 임베딩: `glintr100.onnx` (ArcFace R100)
- 둘 다 Phase 0 에서 `models/insightface/models/antelopev2/` 에 확보됨

**임계값은 화풍별로 다르다.** `style.yaml` 의 `identity_threshold` 를 읽는다.

| 화풍 | 임계값 | 근거 |
|---|---|---|
| vangogh | 0.50 | 구조를 유지하므로 높은 유사도가 가능 |
| halloween | 0.35 | 분장이 얼굴을 바꾸므로 필연적으로 하락 |

고흐 기준(0.50)을 할로윈에 적용하면 정상 결과물이 전부 실패로 찍힌다.

**얼굴 미검출은 0점이 아니라 별도 상태(`no_face`)로 기록한다.**
0점으로 뭉뚱그리면 "닮지 않았다"와 "얼굴이 사라졌다"를 구분할 수 없는데,
후자는 워크플로우가 붕괴한 심각한 실패다.

### 2. 스타일 충실도 — CLIP 유사도

두 가지 방식을 모두 지원한다.

- **텍스트 기준**: CLIP 텍스트 임베딩("a painting by Vincent van Gogh, thick
  impasto brushstrokes")과 결과 이미지의 코사인 유사도.
  참조 이미지가 없어도 즉시 쓸 수 있다.
- **이미지 기준**: `eval/refs/<style>/` 의 진품 셋과의 평균 유사도.
  참조가 확보되면 이쪽이 더 정확하다.

할로윈은 참조 진품 셋이라는 개념이 없으므로 텍스트 기준만 쓴다.

### 3. 미적 품질 — LAION aesthetic predictor

CLIP ViT-L/14 임베딩 위에 얹는 선형 회귀 헤드. 1~10 점.
"잘 그려졌는가"를 대략적으로 판별한다. 절대값보다 **조합 간 상대 비교**에 쓴다.

## 종합 점수

세 축을 하나로 합치지 않는다. 가중치를 임의로 정하면 그 가중치가
결과를 지배해버린다. 대신 **파레토 정렬**한다.

1. `identity >= threshold` 인 것만 후보로 남긴다 (하드 필터)
2. 남은 것을 style 과 aesthetic 으로 파레토 프론트 추출
3. 프론트 위의 조합만 사람이 본다 (보통 5~15개)

240장을 5~15장으로 줄이는 것이 이 지표의 목적이다.
최종 선택은 사람이 한다.

## 저해상도 입력 취급

test2/3/4 는 원본이 354px 로 얼굴이 약 200px 였다 (원본 354px).
ESRGAN 을 거쳤어도 없던 정보가 생기지는 않는다.

-> 리포트에서 **해상도 그룹을 나눠 집계**한다.
   고해상도군(test1/5/6)과 저해상도군(test2/3/4)의 점수를 같은 표에서
   비교하면 워크플로우 문제와 입력 문제가 섞인다.

**미적 점수는 해상도군을 가로질러 비교하지 않는다.** 실측 결과
저해상도군 6.05 > 고해상도군 5.81 로 역전됐다. ESRGAN 이 피부를 매끈하게
다듬은 것을 aesthetic predictor 가 선호하기 때문이다.
정체성 지표는 이 편향의 영향을 받지 않는다.

## 구성

```
eval/scripts/
├─ metrics/
│  ├─ identity.py    ArcFace 코사인
│  ├─ style.py       CLIP 텍스트/이미지 유사도
│  └─ aesthetic.py   LAION aesthetic predictor
├─ naming.py         스윕 결과 파일명 규약 (파싱/생성)
├─ evaluate.py       입력-출력 쌍 채점 -> CSV
├─ report.py         파레토 정렬 + 랭킹
└─ sanity_check.py   지표 자체의 검증
```

## 파일명 규약

파라미터를 파일명에 인코딩해 별도 메타데이터 없이 채점한다.

```
<입력이름>__d<denoise>_cn<controlnet>_lora<weight>_s<seed>.png
test1__d0.65_cn0.70_lora0.80_s12345.png
```

ComfyUI 가 뱉은 결과를 그대로 스캔해 채점할 수 있고,
중단 후 재개해도 이미 만든 것을 다시 만들지 않는다.

## 사용

```bash
python eval/scripts/evaluate.py --style vangogh          # 채점 -> CSV
python eval/scripts/report.py   --style vangogh          # 파레토 정렬
```

출력은 `eval/reports/<style>/<timestamp>.csv`.

리포트는 실패 진단을 먼저 낸다. 얼굴 미검출이 있으면 어느 파라미터 조합에서
발생했는지 집계해 보여준다 — denoise 가 너무 높은 구간을 바로 찾을 수 있다.

정체성 필터는 조합의 **최소값**(`id_min`)으로 건다. 평균으로 걸면
일부 입력에서 얼굴이 무너져도 통과해버린다.

## 검증 방법

지표 자체가 맞는지 확인하지 않으면 신뢰할 수 없다. 세 가지 새너티 체크를 둔다.

1. **자기 유사도**: `identity(x, x)` 는 1.0 에 가까워야 한다.
2. **타인 유사도**: test1~6 은 서로 다른 인물이므로 교차 유사도는 낮아야 한다.
   (같은 인물 vs 다른 인물의 분포가 겹치면 지표를 못 쓴다)
3. **스타일 민감도**: 원본 사진 vs 명백한 회화풍 이미지의 style 점수가
   유의미하게 갈려야 한다.


## 영역별 채점 — 철회 (2026-08-31)

> **아래 내용은 SDXL 노선 기록이다.** 스택을 FLUX+PuLID 로 옮기면서
> 배경·의상이 통째로 생성물이 되었고, "전체 점수는 높은데 배경만 안 바뀐"
> 실패 모드가 사라졌다. 따라서 영역별 채점은 더 이상 쓰지 않는다.
> `eval/scripts/metrics/region.py` 는 남겨 두되 파이프라인에서 빠졌다.
>
> 현재 채점은 `eval/scripts/score_matrix.py` — 정체성/화풍/심미 3축을
> **가중합 없이** 따로 낸다. 축끼리 상충하므로(정체성을 지킬수록 화풍이 약해진다)
> 하나로 뭉개면 어느 쪽이 문제인지 안 보인다.
>
> 판정 문구는 생성 프롬프트와 별도로 짧게 적는다. 생성 프롬프트를 그대로 쓰면
> 자기 자신을 채점하는 꼴이라 항상 높게 나온다.

### (이하 기록) 영역별 채점 (2026-08-31 추가)

요구사항 b(의상)/c(배경)는 이미지 전체 CLIP 점수로 검증할 수 없다.
할로윈 1차 실측에서 전체 0.1825 인데 배경은 0.0746 이었다 —
전체 점수가 배경 실패를 가리고 있었다.

### 왜 crop 이 아니라 패치 샘플링인가

배경 마스크의 바운딩 박스는 이미지 전체다. 잘라내도 인물이 그대로 들어온다.
대신 **해당 영역이 순도 80% 이상인 정사각 패치**를 최대 8장 뽑아
CLIP 점수를 평균낸다.

패치 크기는 min(W,H) x 0.28 에서 시작하고, 영역이 얇아 하나도 안 잡히면
0.7배씩 줄여 재시도한다(하한 64px). 머리카락처럼 9% 대 영역도 이렇게 잡힌다.

### 영역별 프롬프트

전체 프롬프트로 배경 패치를 재면 'portrait' 같은 인물 어휘가 섞여
점수가 왜곡된다. `style.yaml` 의 `region_prompts` 에 영역별 프롬프트를 둔다.

```yaml
region_prompts:
  background: "misty graveyard at night with jack-o-lanterns, fog, ..."
  clothing: "a gothic halloween costume with high collar, velvet and lace"
```

### 한계

마스크는 **입력 이미지** 기준으로 만든 것을 재사용한다.
ControlNet/InstantID 가 구도를 유지하므로 근사가 성립하지만,
`concept_transform`(denoise 1.0)에서는 구도가 이동할 수 있어 오차가 커진다.

### 첫 적용 결과 — 전체 점수가 숨기던 것

할로윈 (원본 = 기준선):

| 구성 | face | hair | clothing(b) | background(c) | 전체 |
|---|---|---|---|---|---|
| 원본 | 0.1730 | 0.1969 | 0.1242 | 0.0706 | 0.0947 |
| CN 있음 | 0.1731 | 0.1973 | 0.1529 | 0.0888 | 0.1825 |
| CN 제거 | 0.1747 | 0.2002 | **0.1829** | **0.0925** | 0.2094 |

원본 대비 개선폭:

| 영역 | 개선 | 판정 |
|---|---|---|
| clothing | +47% | 요구 b 충족 |
| background | +31% | **요구 c 미달** — 절대값이 원본에서 거의 못 벗어남 |
| face | +1% | — |

**face 가 +1% 라는 것이 결정적 단서다.** denoise 1.0 에 ControlNet 도 껐는데
얼굴이 안 바뀐다는 것은 InstantID 가 얼굴뿐 아니라 **화면 전체를
초상 사진 쪽으로 붙들고 있다**는 뜻이다. 배경이 안 바뀌는 원인도 여기에 있다.
