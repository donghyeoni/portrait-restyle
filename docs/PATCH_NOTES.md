## 2026-09-24 — 추석 시리즈 서비스 공개

9월 23일에 만든 추석 7종을 서비스에 올려 공개했다. 따로 추석 팩을 두지 않고 **평소 카드 팩에서 모든 카드와 함께 나온다**.

- 🚀 **공개** — 기존 회원 176명 × 7장 = 1,232장을 공개 전(SCHEDULED) 상태로 미리 만들어 두고, 관리자가 준비 현황을 확인한 뒤 한 번에 공개했다. 최종 **1,169장**이 공개됐다. 공개 뒤 가입하는 회원은 가입 카드와 함께 7장을 바로 받는다.
- 🔧 **뽑기 확률 유지** — 물고기·문어·상어·오징어·거북(N)은 "동물 코스튬"으로 분류해 12지신과 동물 칸(25%)을 나눠 쓴다. 표시 확률(원본 사진 50 · 직업 25 · 동물 25)은 그대로다. 한복·윷(R)은 R 풀에 합류한다.
- 🔧 **추석은 안경 보정 끔** (`glasses: "off"`) — 탈·코스튬 위에 안경 제거 보정을 거칠 이유가 없어, 안경 착용자도 다른 회원과 같은 합성 경로로 처리한다.
- 🔧 **GFPGAN 워커 반영** — 9월 23일 "배포 전 필요"로 남긴 항목이다. `gfpgan`·`basicsr`와 첫 실행 때 받던 가중치(약 185MB)를 워커 이미지에 미리 넣고, 추석 참고 이미지·마스크를 함께 옮겼다.
- 🐛 **완료 보고에 공개 정보 누락** — 공개 전 카드는 완료 콜백에 어느 공개 작업의 카드인지(`releaseId`·`themeCode`)를 되돌려줘야 하는데, 워커가 이 값을 빼고 보내 백엔드가 409로 거절했다. 72장이 처리 임대 만료로 실패했고, 워커가 받은 값을 그대로 돌려주게 고친 뒤 다시 넣어 **전부 복구**했다.
- 🐛 **얼굴 인식 불가 회원 제외** — 9명(63장)은 원본 사진에서 얼굴을 찾지 못했다. 이 9명은 가입 때 직업·12지신 20장도 같은 이유로 모두 실패해 있었다. 다시 넣어도 또 실패하므로 공개 대상에서 빼고 나머지로 공개했다.
- 🔧 **카드 한 줄 문구** — 카드 좌측 하단의 한 줄 문구가 추석 7종에만 비어 있었다. 7종 문구를 새로 붙였다.

### 🔗 백엔드 연동 작업 (담당 범위 밖 · 팀 백엔드 저장소, Spring · 프런트)

- 🔗 **테마 컬렉션 공개 작업** — 가입 카드 23장 규칙은 기본 컬렉션에만 적용하고, 공개된 테마 컬렉션은 가입 계획 뒤쪽(순번 101~)에 덧붙인다. 관리자 화면에서 공개 작업을 만들 때 공개할 컬렉션을 고르고, "카드 준비·동기화"로 기존 회원 카드를 만들고, 공개 버튼으로 공개한다.
- 🔗 **동기화가 실패 카드 처리** — 실패가 하나라도 남으면 공개할 수 없다. 그래서 동기화 때 다시 해 볼 수 있는 실패는 다시 넣고, 원본 사진 문제로 난 실패는 공개 대상에서 빼 그만큼 예상 장수를 줄인다.
- 🔗 **추석 카드 문구** — 프런트의 카드 문구 목록에 추석 7종을 추가했다.

## 2026-09-23 — 추석 컬렉션(N) 추가 · inswapper 합성 옵션 분리

추석 코스튬 7종(물고기·한복·문어·상어·오징어·거북·윷)을 12지신·직업과 같은 inswapper 경로에 올렸다. 입력 28명 × 7종 = 196장을 GPU 0에서 생성·검수했다. **아직 서비스에 배포하지 않았다** (아래 "배포 전 필요" 참고).

- ✨ **추석 매니페스트** (`manifests/chusoek.yaml`, 기본 N · 한복·윷은 R) — 참고 이미지의 얼굴 높이가 화면의 7~22%(평균 12%)로 12지신(11%)과 같은 범위라 엔진 변경 없이 들어갔다. 남녀 파일 이름에 붙어 있던 `_male`/`_female`을 떼어 프리셋 키 하나로 양쪽을 찾게 했다. 화풍이 맞지 않는 moon(달 속 얼굴 + 만화 캐릭터)·puff(복어)는 뺐다.
- 🔧 **프리셋별 등급** — 한복·윷을 R로 올렸다. 백엔드 카탈로그(`catalog_payload`)는 원래 프리셋 `rarity`가 컬렉션 `tier`를 덮었고, CLI 목록(`catalog()`)만 컬렉션 값을 써서 둘이 어긋날 수 있던 것을 같은 규칙으로 맞췄다. 한 컬렉션 안에 두 등급이 섞이는 첫 사례다.
- 🔧 **합성 옵션을 매니페스트로 분리** (`Collection.swap_opts`) — 컬렉션 값을 프리셋 값이 덮는다. 옵션이 없는 직업·12지신은 예전 기본값(keep / upper / 0 / false) 그대로다.
  - `bangs: drop` — 모델들이 머리를 넘겨 이마가 드러나 있어, `keep`이면 멤버 앞머리가 **반쯤 지워진 어두운 얼룩**으로 남았다. 앞머리를 옮겨 붙이는 방식도 만들어 봤지만 후드 위로 머리카락이 얹혀 채택하지 않았다. 직업·12지신은 후드가 이마를 가려 드러나지 않던 문제다.
  - `crop: fit` — 얼굴 기준 상반신 확대 크롭이 물고기 꼬리·윷가락·상어 꼬리·한복 치마를 잘랐다. 배경이 아닌 픽셀 전체를 감싸는 가장 작은 7:9 창으로 바꿔 **코스튬을 하나도 자르지 않고** 빈 여백만 덜어낸다. 원본을 통째로 줄이고 여백을 채우는 방식은 그라데이션 배경에 이음매가 생기고 가장자리에 닿은 손이 잘려 버렸다.
  - `restore: 0.4` — inswapper 출력(128px)이 선명한 참고 사진 위에서 얼굴만 뭉개져 보였다. GFPGAN을 40%만 섞어 눈·치아를 살린다.
  - `face_mask` — 얼굴 구멍이 뚫린 탈에서 붙여넣기 영역이 구멍 테두리의 검은 선을 덮어 흐린 띠를 만들었다. 얼굴 파싱(피부·눈썹·눈·코·입) 안쪽에만 교체 결과를 쓴다. 탈이 아닌 한복은 끈다 — 켜면 턱선이 모델 쪽으로 돌아가 유사도만 떨어진다.
- 🧪 **복원 강도 스윕** (문어·복어, 8명, antelopev2 원본 유사도) — 없음 **0.7012** / GFPGAN 60% 0.6828 / 강한 마스크(경계 3%·페더 2%) 0.6686 / 둘 다 0.6484 / **채택안(40% + 경계 1%·페더 1.2%) 0.6669**. puff를 빼기 전 28명·8종 전체 평균은 0.7441 → 0.7223. 선명도를 얻는 대신 정체성을 조금 내준 절충이다.
- 🐛 **사전 누끼 마스크 오적용 방지** (`steps/refmask.py`) — 마스크 검증이 참고 이미지 해시와 `above`만 봐서, 크롭 방식이 바뀌어도 **상반신용 마스크가 검사를 통과해 전신 카드에 씌워질 뻔했다**. 마스크 메타에 `crop`을 기록하고 대조한다. `crop`이 없는 예전 파일은 `upper`로 보므로 직업·12지신 마스크는 그대로 유효하다. 추석 마스크는 `--force` 없이 다시 돌려 기존 16개가 전부 거부·재생성되는 것으로 확인했다.
- 🔧 **윷 참고 이미지 교체** — 기존 남성 윷은 누끼를 검은 바탕에 거칠게 얹은 것이라 가장자리에 빨강·노랑·초록 1px 얼룩이 있었다. 새 이미지(어두운 스튜디오, 여성 모델)로 바꿨다. 남녀 공용으로 쓰니 남성 유사도가 0.738 → **0.661**로 떨어지고 넘긴 머리·화장이 남아 여자처럼 보였다. 얼굴 교체로는 머리·화장을 바꿀 수 없어, **FLUX Kontext로 같은 이미지의 사람만 남성으로 바꾼 남성용 참고 이미지**를 만들었다(탈·손·윷가락·조명·배경 유지). 후보 4개 중 앞머리 있는 짧은 머리가 남성 14명 평균 **0.757**(넘긴 머리 0.707)로 이전 윷보다도 높았다. 운영 ComfyUI(GPU 1)와 분리하려고 GPU 0에 커스텀 노드를 끈 임시 인스턴스를 따로 띄웠다.
- ⚡ **생성 위치** — 252장(9종 시절) 기준 EC2 CPU 2코어 약 13분 → GPU 0 **41~45초**. 복원·얼굴 마스크를 켠 뒤 224장이 129초.

**배포 전 필요**: `gfpgan`·`basicsr`가 워커 이미지에 없다(basicsr는 최신 torchvision에서 `functional_tensor` 호환 처리가 필요 — `restorer()`에 넣어 둠). GFPGAN이 첫 실행에 얼굴 검출·파싱 가중치 약 185MB를 내려받으므로 이미지에 미리 넣어야 한다. 참고 이미지·마스크는 저장소 밖(`data/`)이라 따로 옮겨야 하고, 백엔드 프리셋 등록도 별도다.

## 2026-09-22 — 카드 생성 중단 복구 · GPU 스택 수명 문제 규명

3일 동안 가입은 되는데 카드가 한 장도 완성되지 않았다. 원인이 셋이었고 서로 가려서 하나씩 벗겨내야 했다.

- 🐛 **GPU 스택이 주피터 세션과 함께 죽는다** — 9월 19일 단일 사용자 서버가 종료되면서 ComfyUI·GPU 서비스·GPU 워커·역SSH 터널 **넷이 한꺼번에** 사라졌다. 호스트는 재부팅된 적이 없다(가동 29주). 터미널에서 띄운 프로세스는 세션에 묶이므로, 주피터가 한 번 내려가면 네 가지를 모두 다시 올려야 한다. 복구 순서는 `start-gpu-stack.sh`(GPU 1 + 서비스) → 역터널 → `start-workers.sh`.
- 🐛 **`start-workers.sh`의 GPU 대기 교착** — 워커를 붙이기 전에 `/health`의 `modelsLoaded:true`를 최대 120초 기다리는데, GPU 서비스는 **가중치를 첫 생성 요청에 지연 로드**한다. 일이 들어오기 전에는 참이 될 수 없어 항상 시간 초과 후 GPU 워커를 조용히 건너뛴다. `WAIT_GPU=false`로 띄워 해결. 갓 기동한 서비스의 `modelsLoaded:false`는 고장이 아니다.
- 🚀 **복구 및 검증** — 밀려 있던 N카드 **120건**과 R·SR **18건**을 전부 소진하고 큐를 0으로 되돌렸다. 복구 직후 실사용자 카드 3종(CYBERPUNK·VAMPIRE·WEBTOON)이 이미지·누끼 키까지 채워 정상 생성됨을 S3에서 직접 내려받아 확인했다.
- 🧪 **누끼 엔드포인트 재확인** — 터널 경유로 `/card-cutout` 200(첫 호출 16.9초, 모델 로드 포함), `/cutout` 200(9.7초, RGBA 896×1152). 9월 16일 이관 구성이 그대로 동작한다.
- 🐛 **장애 구간 손실** — 완료 보고가 막힌 동안 처리 임대가 만료된 39건과, 터널이 끊긴 동안의 누끼 실패 5건은 되살아나지 않는다. 해당 카드는 재요청이 필요하다.

### 🔗 백엔드 연동 작업 (담당 범위 밖 · 팀 백엔드 저장소, Spring)

- 🔗 **아이템 완료 잠금 쿼리 수정** — 계절 SSR 작업으로 완료 대상 조회에 테마 릴리스 테이블이 LEFT JOIN 되면서, 뒤에 붙던 조건 없는 `FOR UPDATE`가 외부 조인의 널 가능한 쪽까지 잠그려 해 PostgreSQL이 문장을 거부했다(`FOR UPDATE cannot be applied to the nullable side of an outer join`). 완료 API가 전부 500을 돌려줘 **워커가 만든 카드가 하나도 기록되지 못했다**. 잠금 대상을 아이템·배치 두 행으로 못박아 해결. 운영 DB에서 두 형태를 직접 실행해 오류와 정상 반환을 각각 확인했고, 같은 저장소의 뽑기 쿼리가 이미 같은 이유로 대상을 지정하고 있었다.

## 2026-09-16 — 원본 카드 배포 · 오픈소스 공개 · 누끼 GPU 이관

- 🐛 **EC2 BiRefNet OOM 규명** — 원본 사진 N 카드 누끼를 EC2 CPU 컨테이너로 돌리자 장당 RAM 최대 **7.4GB**로 15GB 호스트가 커널 OOM을 두 번 냈다. int8 동적 양자화(가중치 973MB → 250MB)는 속도만 15% 빨라지고 메모리는 그대로(6.1GB): 피크는 가중치가 아니라 1024×1024 고정 입력의 중간 활성값이다. 아레나 `kSameAsRequested`는 12GB로 더 나빴다.
- ✨ **GPU 서비스 누끼 엔드포인트** — `serving/gpu/service.py`에 `/cutout`(RGBA PNG)·`/card-cutout`(896×1152 lossless WebP, `steps/cardcrop.py`) 추가. Bearer 토큰 필수, `/generate`와 같은 `busy` 락이라 **생성 + 누끼 3종(SR·원본 N·SSR)이 GPU 1에서 직렬**로 돈다. `CUTOUT_CUDA_DEVICE`로 누끼 장치를 분리할 수 있다.
- 🚀 **누끼 경로 전환** — 백엔드 이미지 워커·Gemini 워커·EC2 카탈로그 워커(`CUTOUT_TOKEN_FILE`, `portrait-worker:v2`)가 역SSH 터널로 GPU 서비스를 부른다. EC2 `cutout-cpu` 컨테이너는 정지(롤백용 보관). EC2 여유 RAM **3.5GB → 12GB**.
  - GPU 1(FLUX 상주, 여유 약 1.2GB)에서 CUDA로 동작: 첫 장 6.9s(모델 로드), 이후 **0.4~0.8s**. 원본 사진 N 카드 누끼 **40~60s → 1~2s**(실사용자 5명 확인).
  - SSR 매거진 카드에서 제목 글자·배경이 알파에서 빠지고 인물만 남는 것을 실데이터로 확인.
- 🔧 **카탈로그 워커 예비 누끼** — 사전 마스크가 없는 참고 이미지만 GPU `/cutout`으로 보낸다(`CUTOUT_TOKEN`/`CUTOUT_TOKEN_FILE` 지원).
- 🚀 **원본 카드 실서버 배포** — EC2 워커 이미지 재빌드 + 재생성, 카탈로그에 `ORIGINAL`(N등급) 노출. 라이브에서 직업·12지신 카드 정상 처리(7~12초) 확인.
- ✨ **저장소 공개** — README에 전체 서비스 구조도(Mermaid) + 기여 정리, [API_SPEC.md](API_SPEC.md)(백엔드↔AI 명세) 작성.

### 🔗 백엔드 연동 작업 (담당 범위 밖 · 팀 백엔드 저장소, Spring)

GPU 누끼 이관을 서비스에 연결하기 위해 백엔드 쪽도 직접 수정했다. 이 저장소 코드는 아니지만 같은 날 같은 목적으로 한 작업이라 함께 기록한다.

- 🔗 **원본 사진 N 카드 누끼 흐름 신설** — 가입 사진 처리가 끝나면 이미지 워커가 후속 메시지를 발행해 누끼 서비스를 호출하고, 결과를 S3에 저장해 CUTOUT 미디어로 기록. 카드 조회는 누끼가 있으면 누끼를 우선 표시. Gemini SSR 워커도 같은 누끼 서비스를 쓰도록 연결.
- 🔗 **HTTP/1.1 고정** — Java `HttpClient` 기본 동작(HTTP/2 업그레이드 요청과 함께 본문 전송)에 uvicorn(h11)이 multipart를 잘못 읽어 422가 났다. 클라이언트를 HTTP/1.1로 고정해 해결. 이 저장소의 GPU 서비스도 같은 uvicorn이라 그대로 적용된다.
- 🔗 **누끼 서비스 Bearer 토큰 지원** — 이미지 워커·Gemini 워커가 `Authorization: Bearer`를 보낼 수 있게 해, 토큰이 필수인 GPU 서비스 `/card-cutout`·`/cutout`으로 전환 가능하게 함. 토큰이 비면 기존 EC2 컨테이너 호출과 동일하게 동작.
