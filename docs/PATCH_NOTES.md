## 2026-09-15 — 원본 카드 · 웹툰 용량 최적화

- ✨ **원본 카드(N등급) 신설** — 입력 사진을 카드 규격(896×1152)으로 얼굴 중심 크롭 + 누끼. AI 생성 없이 EC2 CPU에서 처리. 매니페스트 1장 + 엔진 분기(`original`)만으로 추가.
- ⚡ **웹툰 카드 용량 최적화** — 업스케일 배수 2 → 1.44 (1792×2304 → 1290×1659). 화질 손실 없이 **파일 3.2MB → ~1.5MB (−53%)**, 실 전달 WEBP 1.7MB → 1.1MB. 얼굴 100% 확대 비교로 선화 품질 검증.

## 2026-09-14 — EC2 하이브리드 배포 완료

- 🚀 **하이브리드 구성 확정 배포** — 직업·12지신(+누끼)은 EC2 CPU, 컨셉·웹툰(무거운 누끼)은 GPU 서버(46GB). 두 경로 모두 E2E 검증.
- 🔧 워커를 v1 base 큐로 정렬, 콜백 `/internal/v1/**` 프록시 확인.

## 2026-09-11 — 누끼 오프로드 배포 · 메모리 한계 대응

- ⚡ **누끼 CPU 오프로드 배포** (`GPU_IMAGE_ONLY`) — GPU는 그림만, 누끼는 CPU 워커로.
  - GPU 점유/사용자 65s → **46s**, 시간당 처리 **55명 → 78명 (+42%)**, device 메모리 42GB → **20GB**.
  - 근본 원인: 22GB는 모델 크기가 아니라 onnxruntime CUDA 아레나 과할당(실제 모델 ~1GB).
  - 조건: CPU 누끼(15~20s)가 그림(11.5s)보다 길어 GPU를 놀리지 않으려면 **워커 3개 이상** 필요.
- 🐛 **BiRefNet 메모리 한계 규명** — 입력 크기와 무관하게 7~8GB RAM 사용 → 15GB EC2에서 OOM. arena·mem_pattern 비활성/512 축소로도 해결 안 됨(모델 내부 고정 해상도) → 하이브리드 분리로 결정.

## 2026-09-10 — 서비스 가동 · 대규모 최적화

- ⚡ **사전 계산 마스크** — inswapper가 얼굴 영역만 바꾼다는 점을 이용해 참고 이미지별 누끼 마스크를 미리 계산.
  - 직업·12지신 누끼 **14.6s → 0.01s (약 1,460배)**, 카드 계산 ~16s → **~1.5s**.
  - 정확도 **IoU 0.9994~0.9999** (얼굴 밖 픽셀 차 0.008%), 40장 육안 통과.
- ⚡ **워커 병렬화(큐 분리 풀)** — CPU/GPU 큐 분리 + CPU 워커 풀.
  - 배치 23장 makespan 92.2s → **71.4s (−23%)**, 첫 카드 13.5s → **1.9s**.
- 🚀 **알파 GPU 서비스 가동** — CYBERPUNK 실호출 200 / 37.4s(모델 로드 11.7s), 체크섬 일치.
- 🧪 **E2E 1차** — 사용자 1명 23장, **실패 0**, HMAC·체크섬 정상. 초기 총시간 **7분 51초**(직렬).
- 🔧 **실서버 라이브 반영** — 직업·12지신 아이템 총시간 **18~24s → 2.7s** (사전 마스크 + 큐 분리 병렬).
- ⚡ **webp 인코딩 옵션** — IMAGE 무손실 → 품질 95: **515KB → 123KB (4배↓)**, 장당 −0.9초.
- 🔧 콜백 프록시·HMAC 외부 검증(잘못된 키 401, 만료 타임스탬프 401), Gemini는 Developer API로 확정.
